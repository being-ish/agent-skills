# タイトル

## 概要

この runbook が扱うインシデントを 2、3 文で書く。

## 検知

- このインシデントに気づく経路を列挙する
- アラートがあるなら、アラート名と定義へのリンクを書く
- アラートがないなら、利用者からの申告やダッシュボードの目視など気づく経路を書く

## 対処前チェック

- インシデントを確認するコマンドやダッシュボード
- 切り分けの分岐と、その判断基準
- 切り分けの結果が別のインシデントだったときは、該当する runbook へリンクする

## 対処

手順が複数あるときは h3 で 1 つずつ分ける。1 つだけなら h3 を省き、手順を直接書く。

### 手順

対処の手順を 1 つずつ書く。実行するコマンドはコードブロックや `command` の形で書く。実行後、何が出れば次の手順に進んでよいか、もしくは復旧かを書く。

この手順で対処できなかった場合のエスカレーションがあれば書く。エスカレーションする判断基準、連絡先と連絡手段、伝える情報を含める。

## 事後対応

- 記録を残す場所
- 再発防止策の検討と Issue の起票
