# YYYY-MM-DD タイトル

## 概要

何が起きて、どう収束したかを 2、3 文で書く。

## 事実

観測できた事象と実施した操作を書く。

### 影響

- 影響期間、発生から復旧までの時間
- 影響を受けた機能、利用者の範囲と規模
    - 正確に確認できず、かつ事後分析に必要な値は、根拠とともに推定と明記して書く
    - 必要でなければ書かない
- PRD などで定義済みの SLO や指標がある場合、それへの影響
    - 定義がなければ書かない

### 検知

- 気づいた経路とアラート名
- 発生から検知までにかかった時間

### タイムライン

時刻はタイムゾーンを明記する。

| 時刻 | 出来事 |
|---|---|
| HH:MM | 発生 |
| HH:MM | 検知 |
| HH:MM | 対応開始 |
| HH:MM | 復旧 |

### 対応

- 実施した対処とその結果
- 復旧を確認した観測結果

## 判断

事実の節に根拠を持つ分析と判断を書く。
確認できていない事柄は推測であると明記する。

### 根本原因

- 直接の引き金となった事象
- 引き金から仕組みの問題に到達するまでの「なぜ」の連鎖
    - 途中の問いと答えを省略せずに書く
    - 要因が枝分かれする場合はそれぞれの枝を書く
- 到達した仕組みの問題
- 検知が遅れた場合はその理由

### 教訓

- うまくいったこと
- うまくいかなかったこと
- 幸運だったこと、条件が違えば被害が拡大していた点

### アクションアイテム

進捗と担当は Issue で管理する。
日常の作業を増やすルールや仕組みは書かず、自動化やデフォルトの安全化で防ぐ。
効果が費用と時間に見合う対策がなければリスク受容と書く。
暫定対処のままの箇所は、恒久対応かリスク受容かの判断を書く。

| 内容 | 種別 | Issue |
|---|---|---|
| 実行できる粒度で書く | 再発防止 / 検知改善 / 影響緩和 | [#N](リンク) |
