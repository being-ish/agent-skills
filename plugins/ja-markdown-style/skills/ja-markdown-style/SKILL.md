# 日本語 Markdown スタイルガイド

日本語で Markdown 文書を書く、直すときの指針。

機械的に白黒を付けられる規則は同プラグインの PostToolUse Hook が検査する。
このスキルは、Hook では判定できない、書き手の判断が必要な指針を扱う。

## 文書種別

frontmatter の `being-ish` 配下に `kind` を書くと、その種別に合わない検査を Hook が省く。

```markdown
---
being-ish:
  kind: legal
---
```

種別には次がある。

- `legal`、法文書は条文の慣行に従うため次の規則を適用しない
    - 箇条書き内で句点 `。` を使わない
    - 箇条書きは 1 アイテム 1 文

指定がない場合と一覧にない種別を指定した場合は、すべての検査を適用する。

## 規則

### 文章内容

- 常に最新の情報を書く
    - カットオフ時の知識のみで書かない
- 対象読者がすでに知っているであろう知識は書かない
- 断定できる内容のみを書く
    - 必ず書く内容の裏をとる
    - 確証が得られない場合、可能性の示唆が有意義であるなら書いてよい

### 文章構成

- 対象読者のわかりやすさが最優先
    - その他のルールと衝突する場合はわかりやすさをとる
- h4 まで使ってよい
    - 原則 h3 までにまとめる
    - 複雑な概念を説明する場合 h4 を使ってもよい
- 木下是雄「理科系の作文技術」に則って出力する
    - 短い文の連続で書く
        - 逆接や理由など、関連が深いもの以外はつなげない
    - 逆茂木型の文章を避ける
        - 結論を先に短く
        - 根拠を続けて、端的に書く
    - トピックは対象読者がわかりやすい順番に並べる
    - 括弧での補足を使わない
        - 必要な情報は地の文に書く
- 同じ情報を複数箇所に書かない
    - 前後のつながりが自然なところに書き、他からは参照する
- 1 段落には 1 トピックだけを置く
    - 段落の最初の文で、その段落が何の話かわかるようにする
    - 段落の先頭で、前の段落との論理関係を接続表現で明示する
    - 段落内の視点を固定する
        - 主語を変えるときは段落をわける
    - まとめられる段落はまとめ、むやみに段落数を増やさない
- 対象読者が自力で補える中間段階の説明は書かない
- 論証は一方向に進める
    - 反論を処理してから結論を 1 度だけ述べる
    - 結論を繰り返さない
- 否定するときは、根拠を 1 文添える
- 因果を主張するときは、なぜそうなるのかの機構を 1 文で示す
- 複数の要因がある事象を、単一の原因に還元しない
- ツールや手法に言及するときは適用条件を書く
- 挙げた例が主張全体を支えているかを確認する

### 書き方

- 日本語で書く
    - 英語スラング、口語、比喩を混ぜない
    - 技術用語はそのまま使う
- 動詞は目的語との慣用的な組み合わせを選ぶ
    - 空間や操作の比喩を抽象概念に流用しない
        - 情報が閉じる -> 情報が漏れない
        - この文書に置く -> この文書に記載する
- 文の途中で改行しない
- 造語を使わない
    - 正式な用語か一般的な言葉のみ使う
- 専門用語、訳語はその分野で広く使われている語を選ぶ
- 表現を一貫する
    - 同じものは同じ語で書き、言い換えない
    - 専門用語を導入したら以後はその語で通す
- [カタカナ外来語の表記は文化庁準拠](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/naikaku/gairai/index.html)とする
    - 末尾長音を付ける
- 列挙できる内容は箇条書きを使う
    - 箇条書きは 1 アイテム 1 文
    - 同一セクション内に同じ通番で始まる番号付きリストを複数置かない
- 対応関係は表にする
- 情報密度を上げる
    - 非常に簡潔に短く書く
        - ただし、対象読者のわかりやすさが最優先
    - 冗長な表現を使わない
        - 動詞で書けることを名詞 + 形式動詞で書かない
            - 削除を行う -> 削除する
            - 発行を実施する -> 発行する
    - 意味を足さない語を使わない
        - 〜という / 〜することが -> 削除
        - 〜思われる / 〜考えられる -> 断定できないなら issue 化
    - 同じ意味の語を重ねない
        - まず最初に -> 最初に
    - 意味のない修飾や文を書かない
        - 姿勢だけの宣言は削除する
            - 正面から扱う / 掘り下げる / 多角的に
        - 中身を説明しない強調語は削除する
            - 不可欠 / 核心的 / 非常に / 極めて
    - 同じ主張を言い換えて繰り返さない
- 出典は末尾に列挙せず、本文の該当語句にインラインリンクを張る
    - 主張の中身を担う語句に埋め込む
        - [HTTP](https://datatracker.ietf.org/doc/html/rfc9110) には GET メソッドが定義されている -> [HTTP には GET メソッドが定義されている](https://datatracker.ietf.org/doc/html/rfc9110#section-9.3.1)
    - リンク挿入時にリンク先のタイトルなどを書かない
        - [9.3.1 GET 節](https://datatracker.ietf.org/doc/html/rfc9110#section-9.3.1) では -> [HTTP には GET メソッドが定義されている](https://datatracker.ietf.org/doc/html/rfc9110#section-9.3.1)
    - 概念を紹介するときはその概念のみにリンクする
        - [HTTP という現在世界で最も使われているプロトコルがある](https://datatracker.ietf.org/doc/html/rfc9110) -> [HTTP](https://datatracker.ietf.org/doc/html/rfc9110) という現在世界で最も使われているプロトコルがある
- 演出しない
    - 修辞疑問、体言止め、決め台詞で緊張を作らない
    - 危険や帰結を並べて煽らない
    - 説明で足りる箇所は説明のまま書く
- 文中列挙の区切りは中黒 `・` でなく読点 `、` を使う
    - 固有名詞に含まれる中黒はそのまま書く
    - カタカナで書く人名は姓名の区切りに中黒を使う
    - 法文書は条文の慣行に従うため中黒を使って良い
- `**太字**` を基本使わない
    - 強調しないと対象読者に意図が伝わらない箇所だけ使う
    - コード識別子は `バッククォート` で足りる
- コロン「:」で列挙や説明を導入しない

## 手順

1. 対象文書があれば読み込み、語彙や書き方を把握する
    - 文書が大きく全体を読めない場合、編集対象の周辺を読み込む
2. 編集前に対象読者を想定し、ユーザーに報告する
    - 指示や既存文書に手がかりがあれば使う
    - 手がかりがない場合は推測せずユーザーに確認する
3. 編集前に編集対象やテーマについて対象読者が知っていると想定できることをユーザーに報告する
    - 簡潔にリスト形式で
4. 編集前に対象文書で使われている用語を抜き出し、同じ概念に複数の語があればユーザーに報告する
5. 規則と対象文書の語彙や書き方に従って文章を書く
    - 文章内容と文章構成が最優先
    - 新しい概念を書くときは、その文書の既存の語で書けないか確かめる
6. 全体を通読し、規則に違反するところがあれば修正する
    - 矛盾や論理的飛躍
    - パラグラフライティングできていないところ
    - 口語と文語の混在
    - 不自然な動詞の組み合わせ
    - 書き方の規則
